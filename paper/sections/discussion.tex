\section{Discussion}
\label{sec:discussion}

The results presented here strongly suggest three things about \sys{}. First, it is able to write decisive reports. The rater found a firm position more often for \sys{} than for either baseline, and the lexical data also show fewer hedges on nine out of ten motions and more markers of commitment on all ten motions. Second, \sys{} is able to write compact, claim-centered reports, with citations densely interspersed. Third, the recursive composition in the version of \sys{} evaluated in this paper is not able to maintain the connection between a claim and its supporting source. The higher rate of supported claims and evidence use found by the rater is due to the method's tendency to include consistent citations in a compact report, not to correct attribution of claims to sources.

The firm stance of \sys{} reports is partly an artifact of the prompt. This prompt asks the model to argue for the root answer and avoid hedging, which would be expected to lead to many firm positions, even without the decomposition. But the decomposition provides a definite-format root answer for the prompt, and the experiments described here are insufficient to isolate its effect. (\Cref{sec:analysis} also noted that the titles and executive summaries are indeed committed, while half of the conclusions qualify them.) But a likely cause is that the final writing draws on a graph covering both sides of the question, so its balanced content reappears.

To isolate these effects, it would be useful to run three ablations: one that keeps the graph but removes the instruction to take a stance, one that keeps the instruction but removes the graph, and one that requires the conclusion to be in agreement with the title.

The failure of provenance in stage-based composition is due to the fact that a citation number is a pointer to a location in a list of sources. At each level of the graph in the pipeline evaluated in this paper, the source list was being regenerated. It rebuilt the list, but copied the pointers without changing them, so that each pointer in the next stage referenced a different source than the one it had originally pointed to. This is a general risk for any system that has multiple stages of composition with text containing inline citations. For example, a summarizer of summaries or a merging agent integrating outputs from several other agents could make this mistake. And it is invisible: the resulting report will still be well cited, and no reader or automated rubric counting citation markers would notice.

This is avoided by applying two design rules: (1) each source should have a single identifier throughout the course of the entire run and (2) no model should refer to an intermediate result by an identifier that cannot ultimately be resolved to a source. It is easy to verify that the rules are followed using a lightweight lexical audit, such as the one described in \Cref{sec:citations}. (Attribution metrics based on entailment models \citep{rashkin2023ais, gao2023alce} would provide a stronger check.)

The study uses ten motions and six transcripts, which is too small to make accurate estimates. The human scores are given by a single human rater who is blind to the system but is a coauthor and knows about the study. The model-based debate evaluation uses a small model with the unpublished course rubric, and two measures of the human rubric were discarded because their data records were unusable. The paired measurements discussed in \Cref{sec:analysis} are not dependent on human raters, but are lexical proxies. The stance classifications in \Cref{tab:stance} were produced by a single evaluation.

The three systems use different models, search backends, and prompts, so the comparison is a systems one and not just a decomposition one. STORM was designed to write balanced encyclopedia articles, so its poor performance on firm positions on this task is not a flaw. Deep Research's output is in a commercial tool, so its internal model and version are uncontrolled. A controlled test would fix the language model and search API on a flat search agent, STORM, and \sys{}; include the ablations cited here; and measure attribution as in \Cref{sec:citations} for all systems alongside human judgment.

A \sys{} run requires roughly four model calls per leaf and a few per parent node (\Cref{sec:method}), so its total cost increases linearly with the graph size and is many times higher than a one-shot report. Most of the retrieved sources are not used; only \atUsedShare\% of the listed sources are in the body of the report, on median. A bibliography can be shortened without affecting the argument by excluding sources that are not used by any claim.
