\section{Citation Fidelity}
\label{sec:citations}

The rubric in \Cref{sec:experiments} counted a claim as supported when it carried a citation. It did not check whether the cited source actually states what the claim says. Studies of attribution in generative search show that this second check matters, since \citet{liu2023verifiability} found that about a quarter of citations did not support their sentence. This section measures citation fidelity for \sys{}. It introduces an automatic test, validates it on citations known to be correct, applies it to the evaluated reports, and identifies the step in the pipeline at which citations lose their link to their sources.

\subsection{A lexical attribution test}
The test rests on a simple observation. A sentence written from a source tends to share distinctive words with that source, so the source it came from should be more similar to it than most other sources are. For every sentence with bracketed citations, the test therefore ranks all sources available to the document by TF-IDF cosine similarity \citep{salton1988termweighting} between the sentence and the source text. It then records the rank of each cited source as a percentile, from 0 for the best match to 1 for the worst. If citations point to the sources from which claims were written, cited sources should rank near the top. If citation numbers are effectively random, their percentiles should be spread evenly between 0 and 1, with a median of 0.5. Two statistics summarize the result, namely the median percentile of the cited sources and the share of claims whose single best-matching source is among those cited, which is compared with the share expected by chance. The test requires no model calls and can be applied to every report. Because it is lexical, a source that expresses a claim in different words can rank lower than it should, and the validation below measures how much this limitation matters in practice.

\paragraph{Validation.}
A test of this kind is useful only if it can recognize correct citations. The leaf answers of the logged run (\Cref{app:dag}) provide a set of citations that are correct by construction, because each answer is written in a single model call directly from the retrieved excerpts it cites. Against all \atValMeanCandidates{} sources of the run, the cited source is the best match for \atValBestCited{} of leaf claims, compared with \atValBestChance{} expected by chance, and the median percentile of the cited sources is \atValMedianPct{} (95\% interval \atValPctLo{} to \atValPctHi). The evaluated reports cite full web pages rather than excerpts, which contain more unrelated text. The test was therefore repeated using the full text of the logged run's pages, fetched for this analysis. On the \atValPagesMeanCandidates{} pages that returned usable text, the cited page is the best match for \atValPagesBestCited{} of claims, compared with \atValPagesBestChance{} by chance. On both kinds of text, the test clearly separates correct citations from random ones.

\subsection{Results}
\Cref{tab:attribution} and \Cref{fig:attribution} present the results. The ten evaluated reports contain \atEvalClaims{} cited claims and \atEvalPairs{} pairs of a claim and a cited source. Among all sources listed in each report, the median percentile of the cited sources is \atEvalMedianPct{} (\atEvalPctLo{} to \atEvalPctHi), which cannot be distinguished from the value of 0.5 expected under random citation. The best-matching source is cited for \atEvalBestCited{} of claims, close to the \atEvalBestChance{} expected by chance. Restricting the candidates to the sources that a report actually cites, a median of \atEvalCitedMeanCandidates{} per report, gives the same picture, with the best match cited for \atEvalCitedBestCited{} of claims against \atEvalCitedBestChance{} by chance. The final report of the logged run, produced by the same report-writing step, also performs at chance, with a median percentile of \atLogMedianPct. By this test, the citations in the evaluated reports carry little information about which source supports which claim.

Two examples from the theism report illustrate the result. A bullet stating that ``non-theistic systems such as Confucianism, Buddhism, and Stoicism achieved moral stability'' without divine law cites five sources, all of which argue for the existence of God from the moral law. A bullet on ancient Egyptian, Israelite, and Vedic societies cites ``A Beginner's Guide to the Moral Argument.'' The claims may well be accurate, but the cited sources are not where they came from.

\subsection{Mechanism}
\label{sec:mechanism}
The code that produced the evaluated reports is not available (\Cref{app:changes}). The repository version from a week earlier is available, however, together with a run it produced, and it loses the link between claims and sources at two steps. Both steps are consistent with the pattern observed in the evaluated reports, although they cannot be confirmed in the code of the evaluated version itself.

\paragraph{Local numbers read against a merged list.}
Each leaf answer numbers its own sources from [1] to [$k$]. When a parent is composed, the pipeline merges the sources of its children into a single deduplicated list numbered from [1] to [$m$] and instructs the synthesis model to cite by the numbers in that list. The children's answers, however, are passed with their original local numbers. A citation ``[1]'' copied from the second child therefore refers, in the merged list, to the first source of the first child. The middle rows of \Cref{tab:attribution} reproduce this step on the logged run. When the leaf claims' citations are read against the parent's merged list, the best match is cited for only \atOldBestCited{} of claims, mostly those taken from each parent's first child, compared with \atValBestCited{} in the leaves' own numbering. Because every level of the graph repeats the merge, the misattribution compounds as answers move toward the root.

\paragraph{Node identifiers in place of sources.}
The composition instructions generated in Phase 1 ask the synthesis model to credit each child by its node identifier, so that dependencies can be traced, whereas the synthesis prompt asks it to cite sources by number. The two instructions conflict. In the logged run, \dagParents{} nodes were composed, including the root, and three of them, the root among them, followed the composition instructions and wrote references such as ``(node\_3)'' after their claims without any source numbers. The report writer therefore receives a root answer that contains no source citations, together with an instruction to cite by number, and it assigns numbers without any basis for choosing them. This explains why the final report of the logged run performs at chance.

\subsection{Correction}
Both failures disappear if every source keeps a single identity throughout the run. In the corrected pipeline, each source receives one global number when any node first retrieves it, and every leaf answer is rewritten from local to global numbers before it is stored. Children and parents then share one numbering, and the bibliography of the report uses the same numbering. After each composition, node identifiers in a parent's answer are replaced by the global citations of the corresponding children, and numbers outside the parent's sources are removed. Both the synthesis prompt and the composition-instruction prompt now require citation by source number and prohibit citation by node. When the logged run is replayed with this numbering, the leaf claims keep their attribution, with the best match cited for \atFixBestCited{} of claims, the same rate as in the leaves themselves. Whether the report-writing step preserves this attribution end to end can only be established with new runs, which fall outside the scope of this study, but the test above makes that verification inexpensive.

\subsection{Implications}
The supported-claims rate in \Cref{tab:human} counted citation markers. It therefore measures how consistently \sys{} attaches citations, which it does more densely than STORM (\Cref{sec:analysis}), and not whether its claims are supported by the sources they cite. The evaluated reports should not be read as better grounded than the baselines, because the evaluation does not establish this. The same test can be applied to any system that produces inline citations. Neither baseline could be tested here, however, because the STORM exports lacked URLs and the Deep Research reports were not retained.
