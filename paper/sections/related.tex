\section{Related Work}
\label{sec:related}

OpenAI Deep Research \citep{openai2025deepresearch} is a search planning and browsing agent that produces reports with citations. It is trained with reinforcement learning on browsing tasks of the kind collected in BrowseComp \citep{wei2025browsecomp}, in which the response is a short fact that is challenging to find. The goal is to find and cite relevant information, rather than to argue a position. Its intermediate reasoning remains within one context window, without explicit dependencies between sub-questions.

STORM \citep{shao2024storm} generates Wikipedia-like articles. It first discovers different perspectives on a topic, then simulates conversations in which the writers of those perspectives query an expert with search results, then structures the answers into an outline and article. Its sub-questions are generated via discussions throughout research (bottom-up), and its output is intentionally balanced. Since they target surveys, we view them as the strongest summary-oriented baselines rather than systems for argumentation.

Decomposing a problem into sub-problems is a well-studied prompting technique. In least-to-most prompting \citep{zhou2023leasttomost}, decomposed prompting \citep{khot2023decomposed} and self-ask \citep{press2023selfask}, the model generates sub-questions that, when answered, together provide a solution to the original question. Tree of Thoughts \citep{yao2023tot} conducts a search over intermediate steps, ReAct \citep{yao2023react} interleaves reasoning with tool calls, and Graph of Thoughts \citep{besta2024got} generalizes the tree to a graph where intermediate results can merge. These methods are designed for problems with an objective, verifiable answer (e.g., arithmetic, puzzles, short-form Q\&A) and do not generate prose from retrieved evidence, or revise their structure when a combined answer proves incomplete. \sys{} uses decomposition, but extends these ideas by explicitly instructing a model how to compose answers, providing answers conditioned on retrieved evidence, and refining the graph when gaps in the solution are identified.

AutoGen \citep{wu2023autogen}, CAMEL \citep{li2023camel}, and natural-language societies of mind \citep{zhuge2023mindstorms} use multiple language-model agents conversing on roles such as planner, researcher, and critic. The agents pass back and forth messages, but the task structure is not represented, so one agent's output does not formally constrain how another uses it in the final composition. In our design, the argument structure is represented explicitly, via a DAG, so that answers to sub-questions formally constrain how the parent's answer is composed.

Argument mining \citep{lawrence2020argmining} extracts claims and premises from text and their logical relations. Argument generation generates arguments from scratch. \citet{hua2018argument} introduce a seq2seq model conditioned on evidence to generate counter-arguments. Project Debater \citep{slonim2021debater} extracts claims and evidence from a large mined corpus to generate debate speeches. In these methods, the corpora of claims and evidence is fixed, and text generation is done in a single step. In contrast, \sys{} searches the web for evidence and then composes the argument structure before filling it in.

The literature contains studies of how each citation supports the sentence containing its in-text anchor. This is called attribution \citep{rashkin2023ais, liu2023verifiability}. \citet{liu2023verifiability} find, for four generative search engines, that about half of the sentences in the generated text are fully supported, and about three-quarters of the citations support their containing sentence. In another study, \citet{gao2023alce} create a citation benchmark using an entailment model to automatically calculate citation precision and recall. As these studies are on the task of generation conditioned on retrieved passages in a single step, they do not address the more challenging multi-step setting we consider, in which citations must be correct over multiple rounds of composition. We perform a simple lexical test, requiring no additional model, to check whether citations are retained in the composed answer.

We use DSPy \citep{khattab2024dspy} to implement our pipeline. DSPy allows one to write code that interprets each language-model call as a signature, consisting of an input, an output, and an instruction for the model to follow. These calls can then be composed into a program. All signatures are listed in \Cref{app:prompts}.
